About 1 minute. We want to be honest about limits. First, the tax rules. Four rules are still unverified: the USD 250,000 LRS cap, the 5 percent no-PAN rate, whether earlier payments for other purposes use up the 10 lakh threshold, and whether TCS is charged only on the amount sent and not on fees. The GST rate is taken from each provider's fee schedule. Even the threshold and the 2 percent and 0 percent rates come from secondary sources so far, and GST on the currency conversion itself is not modelled. Every output that uses one of these shows an unverified tag, and we will check them against the RBI Master Direction and the Income-tax Act before final submission. Second, the product. The AI model is an offline, deterministic stand-in; no hosted model is connected yet. Our Ed25519 code is plain Python: it is fine for a sandbox, but it is not constant-time and not audited, so production would use a vetted library or hardware keys. The demo keys are synthetic, and the single trust root would need to be kept offline in a real system. Addresses, and names that appear without a label, are not masked yet, and scanned PDF invoices can't be read because there is no OCR. The demo PIN is fixed so judges can try it. And the audit log shows tampering, but someone who can rewrite the whole file could rebuild the chain. Everything is synthetic, no real money moves, and none of this is tax advice. Thank you.

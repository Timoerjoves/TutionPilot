Built for families: sign-in, vault, next action

Passwordless sign-in

Each device signs a one-time challenge with a key that never leaves the browser. Roles are fixed at sign-in: a student can never act as the parent.

New devices need two locks

The parent’s PIN and a signature from an enrolled parent device over the exact request. Knowing the PIN alone no longer adds a device.

Encrypted family vault

Admission letters and receipts are locked in the browser: AES‑256‑GCM, with a key wrapped for each allowed device via X25519. The server holds ciphertext only.

Asks once, then resumes

A missing due date gets one targeted question. The agent picks its next action from the current state and never re-runs a finished check. Reads PDF, JSON or text invoices.

About 1 minute. Four things we added for real families. First, sign-in without passwords: each parent or student device makes its own key, which never leaves the browser, and signs a fresh one-time challenge from the server. The role is fixed at sign-in, so a student session can never become a parent session. Second, adding a device needs two locks: the parent's PIN, and a signature from a parent device that is already enrolled, over the exact request. Someone who only knows the PIN can no longer add their own device. Third, an encrypted family vault for documents like the admission letter: files are encrypted in the browser with AES-256, and the file key is locked separately for each allowed device. The server only ever stores ciphertext, so it cannot read them. Fourth, the agent decides its next step from the current state. If the invoice has no due date, it asks one targeted question, then resumes without repeating the signature check. Invoices can be PDF, JSON or text.
